# B1500A Test Agent

A safety-gated measurement kernel for the Keysight B1500A Semiconductor Device Analyzer, built to be driven by
coding agents (Codex CLI and Claude Code) without letting them send raw instrument commands.

A typed Python core plans, checks, runs, archives and analyzes measurements. Two thin adapters expose it: an MCP
server with ten outcome-level tools and the `b1500` CLI. Every executable action is a **recipe**. It runs only
through `validate_plan → run_plan` or, when a human must confirm, `run_confirmed_plan`, and the core enforces
limits, tiers, per-command output guards and a verified safe shutdown. A simulator of the whole station stands in
for the instrument, so everything is developed and tested without hardware.

> **Status (2026-11-26): v2 built and closed on the simulator (M5–M11); the final harness acceptance S1–S18
> (WP11.5) passed on Codex and Claude Code; the hardware session M12 is the owner's.** The whole station is covered: SMUs with the GNDU, the MFCMU
> (+SCUU, QSCV), the HV-SPGU with two 16440A selectors and the WGFMU with its RSUs, in 68 recipes, 14 measurement
> kinds and 34 test cards, every recipe `sim_validated` against the simulator's device models and run through the
> real VISA transport against the simulator (visa-loop) and through a fake of the WGFMU library's C interface. The
> gate (tests, lint, recipe check, skill lint, card index, coverage page, skill mirror, tool budget, manual corpus,
> `doctor`) runs in CI on macOS and Windows. Three skills (`b1500-test`, `b1500-debug`, `b1500-bringup`) guide the
> agent; the acceptance scenarios passed on both harnesses at every module closure
> ([docs/acceptance/](docs/acceptance/)). **No code path has run against a real instrument yet:** the lab bring-up
> (stages S0–L10, [docs/hardware-bringup.md](docs/hardware-bringup.md)) is the owner's session M12
> ([docs/roadmap.md](docs/roadmap.md)).

## Scope

| Module | What runs |
|---|---|
| SMU (HRSMU, MPSMU) + GNDU | spot, staircase sweeps (V/I, lin/log, double, synchronous, multi-channel), pulsed spot/sweep, sampling with time stamps, linear/binary search, quasi-pulsed breakdown, QSCV, stress-measure (BTI, HCI, SILC, IGZO bias stress, TDDB), compact-model fit and SPICE netlist |
| MFCMU (+SCUU) | phase compensation and open/short/load correction with a correction store, spot C, C-V, pulsed C-V, C-f, C-t, C vs AC level, multi-frequency C-V and Dit, split C-V, FeCap butterfly |
| HV-SPGU + 16440A | 2-/3-level pulse trains and ALWG sequences through the selectors, charge pumping, FeFET program/read, switching kinetics, endurance, retention |
| WGFMU + RSU | pulsed and fast I-V, pulse trains, the lab's waveform CSV files, DC spot, RTN and 1/f noise, fast BTI, FeCap PUND and endurance, fast FeFET program/read |
| Mainframe | identity, inventory, errors, self-test and self-calibration (FLEX and WGFMU library), zero check, selector check |

Per module the kinds, recipes, cards, rules, simulator models, bring-up stages and the legacy-ledger counts:
[docs/coverage.md](docs/coverage.md), generated by `uv run b1500 dev coverage --write`. Out of scope with reasons
(blueprint v2 §1.2): above 42 V or 100 mA, free-running pulses, EasyEXPERT remote control, program memory, running
an external SPICE simulator.

## Layers

The eight layers of the owner's design deck and where they live:

```text
L8 Agent           Codex CLI / Claude Code          AGENTS.md, CLAUDE.md, harness config (generated per machine)
L7 Skills + rules  b1500-test/-debug/-bringup       .agents/skills/  rules/  config/*.example  manuals/ (corpus)
L6 MCP + CLI       10 tools, `b1500` CLI            service/  adapters/{mcp_server.py, cli/}  bringup.py
L5 Analysis        quality, extraction, plots       analysis/  archive/
L4 Transaction     recipes, kinds, lock, cleanup    catalog/  recipes/  session/
L3 Driver          FLEX builders, guard, parser     driver/ (flex/ = the only FLEX text, ops/ per family, wgfmu.py)
L2 Transport       VISA, WGFMU library, simulator   transport/  transport/wgfmu/ (ctypes)  transport/sim/
L1 Physical safety interlock, shield box, wiring    station profile, bring-up stage S0, 42 V / 100 mA code ceiling
```

Dependencies point downward only: `adapters → {bringup →} service → {catalog, rules, archive, analysis, manuals} →
session → driver → transport`, with `models` as a shared leaf (import test). Details:
[docs/architecture.md](docs/architecture.md); safety design and residual risks:
[docs/safety-model.md](docs/safety-model.md).

## Quick start (development machine, simulator only)

Requires [uv](https://docs.astral.sh/uv/) and Python 3.11–3.13. From the repository root:

```bash
uv sync                                                        # creates .venv/ in the clone from uv.lock
uv run b1500 doctor                                            # installation and config checks (PASS/WARN/FAIL)
uv run pytest -m "not hardware and not acceptance" -n auto     # simulator, visa-loop and fake-ABI suite
uv run ruff check
uv run b1500 --help                                            # operator, human-only and developer commands
```

A first measurement on the simulator (every value is marked SIMULATED):

```bash
uv run b1500 status
uv run b1500 recipes --family smu
uv run b1500 plan mosfet.idvg --pin-map mosfet-4t --dut nmos-generic   # prints plan_id, tier and summary
uv run b1500 run PLAN_ID                                                # tier ok: runs; archives data/runs/...
uv run b1500 analyze RUN_ID vth_linear_extrapolation                    # Vth, derived, with its fit window
```

The developer gate (blueprint v2 §10, the CI job): the tests above, then `uv run b1500 dev recipe-check`,
`uv run b1500 dev lint-skills`, `uv run b1500 dev gen-index --check`, `uv run b1500 dev coverage --check`,
`uv run b1500 dev sync-harness --check`, `uv run b1500 dev tool-budget` and `uv run b1500 manual status`.

Everything stays inside the clone: `.venv/`, `data/` (run archive and state), `config/local/` (human-owned live
configuration) and `work/` (agent scratch) are gitignored. Only `*.example.yaml` configuration is committed.

## Connect a coding agent

Launch the harness from the repository root. The MCP config is machine-specific (it holds the clone's absolute
path), so it is generated, not committed:

```bash
uv run b1500 harness init --codex     # writes .codex/config.toml (Codex loads it for trusted projects)
uv run b1500 harness init --claude    # writes .mcp.json (Claude Code asks once to approve the server)
uv run b1500 harness init --codex --claude --check    # drift and approval wiring check
uv run b1500 dev mcp-smoke --config .mcp.json         # starts the server as configured: 10 tools, backend sim
```

Committed alongside: `.codex/rules/b1500.rules` (Codex `forbidden` rules), `.claude/settings.json` (Claude Code
allow/ask/deny rules and the `scripts/hooks/b1500_guard.py` hook). `run_confirmed_plan` always asks the human
(Codex `prompt`, Claude Code `ask`); `run_plan` and `safe_shutdown` never do. Never start a harness in a bypass
mode; the human-only commands (`b1500 fault clear`, `b1500 run --confirm`, `b1500 config init|adopt`) are denied to
the agents.

## How a measurement runs

1. The agent reads `station_status` and the recipe list, then calls `validate_plan` with a recipe, parameters, a
   pin map and a DUT profile.
2. The plan gets a tier: `ok` → `run_plan(plan_id)`; `needs_confirmation` → the agent shows the one-line summary,
   stops, and only after the human agrees in chat calls `run_confirmed_plan(plan_id, summary)`, which the harness
   puts in front of the human; `blocked` → never runs.
3. The run executes inside a locked transaction that always ends with abort, SPGU stop, WGFMU safe state, zero,
   switches to rest, disconnect and a verified safe state, and archives raw data, parsed data, the audit log and the
   manifest under `data/runs/`. A plan longer than 5 min runs asynchronously: `get_run` shows its progress and
   partial data, and `safe_shutdown` from any process stops it at its next checkpoint.
4. `analyze_run` extracts parameters (the card's default method, for example Vth by linear extrapolation) from
   trusted points only and reports them as derived, with method and fit window.

Manual facts come from the committed page corpus of the 16 Keysight manuals (2,315 pages), without the PDFs:
`uv run b1500 manual search "ERSSP status"` → `uv run b1500 manual page PG 433` ([docs/manuals.md](docs/manuals.md)).

## Lab PC

The real station is a Windows PC wired to the B1500A over GPIB that runs the same clone (`git clone`,
`uv sync --frozen`, local configuration in `config/local/`). One command keeps it current: `uv run b1500 update`,
typed by the operator, pulls `main`, syncs the environment, repairs the harness wiring, installs the harness versions
the maintainer validated (`config/harness/validated.yaml`) and ends with `Ready.` or a numbered list of what to do.
[docs/deployment-windows.md](docs/deployment-windows.md)
is the owner's first-session script (prerequisites including the WGFMU instrument library A.03.00 or later x64,
the read-only probe `uv run b1500 doctor --probe --wgfmu-session`, the station proposal
`uv run b1500 bringup propose-station`, configuration adoption by the human, harness wiring, an offline
wheelhouse); then the coding agent follows skill `b1500-bringup` stage by stage with the owner
([docs/hardware-bringup.md](docs/hardware-bringup.md)). Reviewed hardware records go to
[validation/hw/](validation/hw/README.md); only they promote a recipe to `hw_validated`.
